**Architecture:**
- **TOC (#41)** — text boxes with `headingLevel` (1–6) emit a `{t:'bookmark', heading:true}` marker. Page assembly keeps headings apart from bookmarks (`model.bookmarks` and the PDF outline do not change) and hands both to the TOC item, tagged with their source. Numbering is a pure function `tocNumbers(entries, numbering)` in `src/engine/items/toc.js`.
- **Images (#40)** — the engine resolves `embedded:<name>` (report-level `images` map), bare base64 from data fields and byte arrays to `data:` URIs at layout time, so every exporter and the viewer see a plain data URI. `src/engine/image.js` sniffs the type and reads the natural size (PNG IHDR, JPEG SOF, SVG width/height/viewBox) without decoding pixels; `autoSize` and `clip` use it. A post-pass resolves `embedded:` in background images. Caps: 10 MB per image, 50 MB per render (unique sources), with warnings. The PDF exporter draws SVG images as vector paths through pdf-lib's `drawSvgPath` (`src/exporters/svgimage.js`) and refuses PNGs above 40 megapixels (decompression bombs).
- **Barcodes (#39)** — a symbology table (`SYMBOLOGIES`: bcid, friendly name, 2D flag, sample, input cap) and a whitelist mapper `bwipOptions(item)` that turns flat item keys into bwip-js options with enum and range checks. No user key reaches bwip-js unfiltered. Input over a symbology's capacity is refused before bwip-js runs. Rotation reuses the Phase 1 per-item `rotate` page-model field.
- **PDF encryption (#38)** — `src/exporters/encrypt.js`: the standard security handler, **revision 6, AES-256 (V5, StdCF AESV3)**, ISO 32000-2 §7.6.4. It needs only SHA-256/384/512 and AES-CBC, which WebCrypto (`globalThis.crypto.subtle`) has in browsers and Node 20+: no injected function, no new dependency. It runs on pdf-lib's object graph after `doc.flush()` and before `save({ useObjectStreams: false })`: every string becomes a `PDFHexString` of ciphertext and every stream a `PDFRawStream` of ciphertext; nothing is concatenated into PDF syntax. PDF/A + encryption and signing + encryption are refused (400).
- **Designer embed (#37)** — `src/embed/designer.js` exports `mountDesigner`, a second ESM entry of the embed build sharing chunks with the viewer (the offline single-file viewer stays designer-free). The designer gets an `embed` prop: `onSave`, `onOpen`, `readOnly` (guarded in `store.apply`, the one mutation path), `toolbox.hide`, `panels`, `dataSourceTemplates`. Keyboard handling uses `composedPath()` so typing inside the shadow root counts as typing. `next/link` is aliased to a plain anchor in the embed build.
- **Framework packages (#36)** — `@pagewright/react`, `/vue`, `/svelte` (a Svelte action: no compiler needed) and `/angular` (custom elements `<pagewright-viewer>` / `<pagewright-designer>`, used with `CUSTOM_ELEMENTS_SCHEMA`: an Angular component needs the Angular compiler, custom elements do not). Peer dependencies only. Engine and viewer `.d.ts` are generated from JSDoc with `tsc --declaration --allowJs --emitDeclarationOnly --noCheck`; `packages/engine/report.d.ts` is hand-written.

**Tech stack:** plain JS + JSDoc, pdf-lib, bwip-js, WebCrypto, esbuild, TypeScript (dev only, for `.d.ts`), Vitest, Playwright.

**Decisions taken without asking (simplest safe option):**
1. **AES-256 R6, not AES-128 R4.** R4 needs MD5 and RC4, which WebCrypto lacks (they would have to be hand-written); R6 needs only SHA-2 and AES. Read by Acrobat X+, poppler, pdf.js and macOS Preview.
2. **The owner password defaults to 32 random bytes** when only a user password is given (nobody can then lift the permissions). **Permissions default to allowed**; set one to `false` to deny it. Passwords are NFKC-normalised (SASLprep's main step) and must be at most 127 UTF-8 bytes; longer is refused, not silently truncated. Errors never contain a password.
3. **Encryption + signing is refused.** Signing after encrypting needs the signature's /Contents left unencrypted and a byte range over ciphertext; the simplest correct answer is no. **Encryption + PDF/A is refused** (PDF/A forbids encryption).
4. **SVG in PDF is drawn, not rasterised** (no 2 MB resvg-wasm). Supported: path, rect (rx/ry), circle, ellipse, line, polyline, polygon, nested `g`, `transform` (matrix, translate, scale, rotate, skewX/Y), fill, stroke, stroke-width, opacity, fill-opacity, stroke-opacity, the `style` attribute. Not drawn (documented): text, gradients, patterns, clip paths, masks, filters, `<use>`, `<style>` sheets, `fill-rule: evenodd` (drawn nonzero). The viewer and the HTML export show SVG natively.
5. **Natural image size is 96 dpi** (1 px = 0.75 pt), as in CSS. `autoSize` sets the box to it when the image is a data, embedded or base64 image; a URL image (size unknown at layout) warns and behaves as `contain`.
6. **Angular ships custom elements** (see Architecture). React and Vue wrappers are plain JS (`createElement`, `h`), no JSX build step.

```js
// src/engine/items/toc.js
const ROMAN = [[1000, 'M'], [900, 'CM'], [500, 'D'], [400, 'CD'], [100, 'C'], [90, 'XC'], [50, 'L'], [40, 'XL'], [10, 'X'], [9, 'IX'], [5, 'V'], [4, 'IV'], [1, 'I']];
export function formatNumber(n, kind) {
  if (kind === 'roman' && n > 0 && n < 4000) { let s = ''; for (const [v, r] of ROMAN) while (n >= v) { s += r; n -= v; } return s; }
  if (kind === 'alpha' && n > 0) { let s = ''; while (n > 0) { n--; s = String.fromCharCode(65 + (n % 26)) + s; n = Math.floor(n / 26); } return s; }
  return String(n);
}
export function tocNumbers(entries, numbering) {
  const kinds = Array.isArray(numbering) ? numbering : [numbering];
  const counters = [];
  return entries.map(e => {
    const L = Math.max(0, Math.min(9, e.level || 0));
    for (let k = 0; k < L; k++) counters[k] ||= 1;
    counters[L] = (counters[L] || 0) + 1;
    counters.length = L + 1;
    return counters.map((c, k) => formatNumber(c, kinds[Math.min(k, kinds.length - 1)] || 'decimal')).join('.');
  });
}
```
