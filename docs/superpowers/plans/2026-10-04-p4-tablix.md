# Phase 4: Tables, pivot tables and pagination Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close audit rows #14–#20 of `2026-10-04-arjs-parity-roadmap.md` (Phase 4): the tablix (pivot table), recursive hierarchies, merged cells and regions in cells, grid lists and footers at the bottom, horizontal pagination, page numbers per section and multi-section reports.

**Design spec:** `docs/superpowers/specs/2026-10-04-tablix-design.md` (read it first; this plan does not repeat it).

**Architecture:**
- The pivot is computed by a pure module, `src/engine/items/pivot.js` (trees, visible rows and columns, cells, percentages, caps). The `matrix` item turns that into explicit table rows and hands them to the `table` layout (`__body`), so pagination, repeated headers, regions (Excel/CSV), Word tags and links stay one code path.
- The table layout grows the shared pieces: `rowSpan` with `cont` labels, per-cell toggles, raw values and cell scopes, cell items, recursive groups, `printAtBottom`, `newSection` markers and a column-slicing post-pass (`src/engine/items/hpage.js`) for horizontal pagination.
- The page assembler in `src/engine/index.js` learns three things: draw `cont` items on the first unit of a page, bottom-align `atBottom` units, and number pages per section. Body sections (an array) are laid out and paginated one after the other, each with its own page.
- Exporters read `page.width ?? model.width` and the Word exporter learns `rowSpan`.

**Tech Stack:** plain JS + JSDoc (`// @ts-check`), Vitest, React (designer), Playwright e2e.

## Design decisions (product choices taken from ActiveReportsJS / RDL)

1. **The item stays `matrix`.** ActiveReports calls it a tablix; renaming would break saved reports and the gallery. The array keys (`rowGroups`, `columnGroups`, `values`) select the new form; the old keys still render the old way, byte for byte.
2. **Totals are per group, RDL style:** `total: before | after` on a group totals that group's instances inside its parent. The first group's total is the grand total.
3. **Collapsed instances aggregate in place** (one row or column with the instance's value), as ActiveReports does when a toggled member hides its children and the parent shows the instance total.
4. **Wide pivots paginate sideways by default** in the new form (ActiveReports does); the old form keeps shrink-to-fit so old reports do not change. Default page order is `down` (RDL "down, then over").
5. **Merged row headers repeat** at the top of a page when the rows under them continue (ActiveReports repeats the header text of a split member).
6. **Recursive groups:** `Level()` is 0-based and 0 outside a recursive group; aggregates are the node's own rows unless the `"Recursive"` argument is given; children follow the node's own content and come before its footer.
7. **`newSection`** names the RDL `ResetPageNumber` behaviour; `OverallPageNumber` / `OverallTotalPages` are the RDL names for the report-wide count.
8. **Multi-section** is the RDL `ReportSections` model: each body section has its own page settings; the page header and footer are shared (RDL lets each section have its own; noted as a gap).
