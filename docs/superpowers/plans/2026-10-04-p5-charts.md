# Phase 5: Charts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close audit rows #21–#28 of `2026-10-04-arjs-parity-roadmap.md`, Phase 5: stacked/100%/range/smooth/step series; axis control with a second y axis; combo charts; bubble, radar, polar, candlestick/OHLC, gauge and funnel; trend lines, moving averages, reference lines and bands; data label templates, positions and collision avoidance; 12 named palettes and viewer-only animations; sparkline area/win-loss/bands, an icon set and a range bar.

**Architecture:**
- Charts stay what they are today: the engine draws every chart as page-model primitives (`rect`, `line`, `path`, `ellipse`, `text`, `link`). The viewer (SVG), PDF, HTML, interactive HTML and the designer canvas draw those primitives and nothing else, so a chart looks the same everywhere with no per-exporter chart code. Word leaves charts out, as before.
- `src/engine/items/chart.js` keeps the data step (`chartData`) and the cartesian charts (column, bar, line, area, scatter, bubble, candlestick, OHLC, combos, overlays, labels). Pure maths moves to a new, unit-tested `src/engine/items/chart-kit.js` (palettes, contrast, scales and ticks, curve paths, regression, moving average, label placement). The round charts (pie, donut, radar, polar, gauge, funnel) go to a new `src/engine/items/chart-round.js`.
- Exporters change in one place only: a `path` item may carry `dash` (SVG `stroke-dasharray`, PDF `borderDashArray`), like `line` and `rect` already do. Trend lines need it.
- Animations: the engine tags chart marks with `anim` (`{k: 'grow' | 'fade', ox, oy, i}`) only when the chart sets `animation`. `pageToSvg(page, w, h, {animate: true})` turns those tags into CSS classes and puts one `<style>` in the SVG. Only the viewer passes `animate`; PDF, HTML, images and the designer stay static.
- Nothing here touches the matrix/tablix, pagination or `src/engine/index.js` (Phase 4 is reworking them in another worktree).

**Tech stack:** plain JS with JSDoc, React function components, Vitest, Playwright (e2e), pdf-lib.

## Decisions taken without asking (ActiveReportsJS behaviour where it has one)

1. **The x axis is the category axis in every orientation** (in a bar chart it is drawn on the left), as in ActiveReportsJS, where swapping axes does not rename them. `xTitle`, `valueFormat` and `categoryFormat` keep working; `axes.*.title/format` win when both are set.
2. **Log axes drop values ≤ 0 with a warning**, as ActiveReportsJS does. Ticks are powers of the base (10).
3. **A 100% stack stacks columns, bars and areas on the same axis.** Lines are not stacked (as before). Ticks read 0%–100%; labels and tooltips show the real value with its share.
4. **Range series** are `low` + `high` on a series: floating bars in a column/bar series, a band between two lines in a line/area series (ActiveReportsJS "range column/bar/area").
5. **Step lines are "step centre"** (the riser sits halfway between two categories). The importer maps StepLeft/StepRight to it with a note.
6. **Smooth lines are monotone cubic** (Fritsch–Carlson), so a curve never overshoots its points (no fake peaks or values below zero).
7. **Combo charts are column + line + area in a vertical chart, and bar + line + area in a bar chart.** Pie/donut/round types ignore per-series types.
8. **Overlay values are expressions in the chart's scope** (`=Avg(Fields.amount)` is the average over the chart's rows). Trend x is the category index for category charts and the x value for scatter/bubble. Polynomial order is clamped to 2–6; the exponential fit uses positive values only.
9. **Data labels are drawn when `showValues` is on or `labelTemplate` is set.** Template placeholders: `{value}`, `{category}`, `{series}`, `{percent}`; a template starting with `=` is an expression in the point's scope. Labels that would overlap a label already placed move once (line: below the point) and are otherwise left out; labels never leave the plot.
10. **Stacked columns and bars now show their values centred in each segment** when values are on. Before, `showValues` was silently ignored on stacked charts; ActiveReportsJS shows them.
11. **Label ink follows contrast:** a label on a filled mark is white or near-black, whichever has the higher WCAG contrast with the fill. Pie percentages were always white (unreadable on amber and lime slices).
12. **Gauges are a half circle** with the value arc, a needle, min/max labels and the value in the middle; `axes.y.min/max` set the range; `band` overlays colour the track and `line` overlays mark targets.
13. **Funnel stages keep the data order** (sort with `categorySort`); each stage is a trapezoid from its value to the next one's.
14. **Polar charts** take `xValue` as the angle in degrees (0 at the top, clockwise) and the series value as the radius, per row, joined in angle order when the series type is `line`.
15. **Animations are opt-in** (`animation`, default none) so no existing report changes; they respect `prefers-reduced-motion`.
16. **Size caps** (data is untrusted): 1,000 categories, 50 series (with a series group, the first 50 groups in sorted order), 10,000 points per scatter/bubble/polar series, 20 overlays, moving-average period ≤ 1,000. Each cap warns. Series grouping is one pass over the rows (it was groups × rows). No `Math.min(...array)` on data-sized arrays (stack overflow above ~100k).

### Changes to this plan while building it

1. **Labels may use the whole chart box, not only the plot**: a value label above the tallest bar sits above the plot, and the old charts drew it there.
2. **Bar labels that do not fit outside move inside the bar** (contrast ink), as ActiveReportsJS does; otherwise the longest bar of a log chart lost its label.
3. **Bubbles keep inside the plot**: the scales are laid out on a plot inset by the largest radius.
4. **Animation origins are sides of the mark's own box** (`transform-box: fill-box`), not absolute points: the paginator moves items after the engine draws them, so absolute origins would be wrong on any page but the first. The gauge needle fades in instead of turning.
5. **Value-axis tick labels in bar charts thin out** (every k-th) when they would touch; vertical value axes use 3 ticks when the plot is shorter than 6 text heights. Neither changes any locked chart.
6. **The point cap for scatter/bubble/polar is per chart** (10,000 points across all series), not per series.
7. **Importer: scatter charts get their `xValue`** (before, an imported scatter chart had none and drew "No data").
8. Found, not fixed (Phase 0 bug, other worktree): an item with `pageBreakBefore` that already moved to a new page because it did not fit leaves a blank page. The showcase does not use `pageBreakBefore`.
